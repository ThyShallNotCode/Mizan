01Chapter

Welcome

مقدمة

Mizan grades multiple-choice answer sheets from their scans. When it is not sure of something, it stops and asks you.

What Mizan does

  • Reads scanned answer sheets: the legacy answer sheet (up to 100 questions, options A–E), or a form Mizan prints for your exam.
  • Scores them against your answer key, one per version: from a file, from answer sheets you fill in, or from Remark Office OMR's Excel export.
  • Sends every doubt to you. A faint mark, an unclear double mark or erasure, an unreadable student number, a student not on the roster, two sheets with one number: each waits in Review. By default, a clearly filled double mark is scored as wrong without review (Second review, Chapter 4).
  • Shows the results (scores, letter grades, item analysis, course learning outcomes) and releases them only when you say so, with nothing left open.
  • Writes files: results in Excel and CSV, item analysis, course-report outcome tables, an HTML report and a Blackboard upload file. Every decision goes into a tamper-evident log in the exam's folder.

Mizan is two programs: omr-desktop, the desktop app this manual describes, and omr, the command line (Appendix A). The screens are in English; Arabic names, grade letters and option letters work.

This is a preview
  • Mizan 0.1.0 is a first version. Grading, review, release and exports work on Linux.
  • The desktop app has been tested only by automatic tests, never in a real window: its file pickers have not been shown on a real display. If one does not appear, type or paste the path.
  • Windows builds are unsigned test builds, not yet tried on an everyday PC, and some protections are missing (Chapter 14). Do not grade real exams on Windows with a test build. There is no Mac version.
02Chapter

Install and first launch

التثبيت والتشغيل الأول

There is no installer yet. You unpack one folder and start the desktop app from it. The first start creates your exams folder.

What you need

  • Linux (64-bit, x86) with a desktop session (X11 or Wayland): works. Mizan's own speed and accuracy tests have run on Linux only.
  • Windows 10 or 11 (64-bit, x86): unsigned test builds that pass the automatic tests, the only tests run on Windows so far. They are not yet tried on an everyday PC, and their speed is not known yet.
  • macOS: not available.
  • A screen of at least 1280 × 800 (the window is normally 1440 × 900), and your scans on a local disk of your institution's device.

Get the program (test build)

WindowsLinux
1From the project's Releases page, download mizan-<version>-x86_64-pc-windows-msvc.zip.Download mizan-<version>-x86_64-unknown-linux-gnu.tar.gz.
2Check the download against the SHA256SUMS file published beside it. Your IT team can help.
3Unzip it. The folder holds omr-desktop.exe (the desktop app), omr.exe (the command line), BUILD.txt, OFL.txt and SHA256SUMS.If they are missing, install two libraries. On Debian or Ubuntu: sudo apt install libfontconfig1 libxkbcommon-x11-0. Then unpack the archive.
4Run omr-desktop.exe.Run ./omr-desktop from a desktop session. Optional: ./install-desktop-entry.sh adds Mizan to your applications menu (run it again if you move the folder).
Important

Test builds are not signed. Windows SmartScreen warns about them, and devices that enforce App Control or AppLocker may block them. Ask your IT team; do not work around the warning. Production releases will be built and signed separately.

First launch

  1. Start Mizan. The first time, it creates and opens the folder OMR Exams in your home folder (on Windows, your user profile folder); on Linux it is created readable by you only. An empty folder shows No exams in this folder yet. Later, Mizan opens the folder you used last.
  2. To use another folder, go to Exams and press Open folder… (Ctrl+O). Choose the folder that holds your exam folders. If you pick the folder of one exam, Mizan opens the folder above it and selects that exam. You can also use Settings › About › Change….
  3. Go to Settings › Review, type your name and press Save (or Enter). Every decision from then on is recorded under that name.
03Chapter

A tour of the window

جولة في النافذة

Mizan has six screens, in the order you work, plus Settings. Every screen shares the same frame: the rail on the left, a top bar and a status bar.

  1. Navigation railThe six screens (Ctrl+1 … Ctrl+6) and, at the bottom, Settings (Ctrl+,). The badge on Review counts open review items.
  2. Top barSearch (Ctrl+K), Open folder… (Ctrl+O), refresh (F5) and New exam (Ctrl+N). On other screens: course / assessment / screen and that screen's buttons.
  3. Light or darkThe moon or sun button switches the theme.
  4. Status filtersAll, Setup, Scanning, In review, Ready to release and Released, each with a count.
  5. TilesSheets scanned this week, open exceptions, median review time, throughput.
  6. Exams tableCourse, assessment, date, forms, sheets, exceptions, status. ↑ ↓ move; Enter opens the drawer.
  7. Details drawerStatus and next step (here Continue review (14)), key, CLO mapping, roster and last scan, and buttons to open the results, setup, scan or folder. Esc closes it.
  8. Status barMessages, the exams folder and the engine version. A notice appears just above it when a run ends.

The screens

ScreenWhat it is for
ExamsEvery exam in your exams folder, its status and its next step.
SetupThe exam's definition: answer key and CLO mapping, roster, key sheets, imports.
ScanA grading run as it happens, its exceptions, and later batches of scans.
ReviewEverything Mizan was not sure about, waiting for your decision.
ResultsScores, item analysis, release readiness, release and export.

The status of an exam

Every exam shows one of five statuses. Setup: no pages yet. Scanning: pages are being read. In review: graded, but something blocks release. Ready to release: nothing blocks it. Released: you released it. A later change, such as a review decision, a new key or more scans, takes a released exam back, and you release again.

If you close the window while an exam is being graded, Mizan asks Close Mizan? with Keep it running and Cancel it and close (or Close once saved when it is too late to cancel). Esc keeps it running.

04Chapter

Create an exam

إنشاء اختبار

New exam turns a folder of scans into a graded exam. Mizan proposes every value from the scans and your files, shows where each one came from, and grades exactly what the card shows.

Have ready the scans (Chapter 6), the answer key (Chapter 5), the roster (recommended) and, for learning outcomes, a CLO mapping file (layouts in Chapter 13).

  1. On Exams, press New exam (Ctrl+N). The New exam card opens over the list.
  2. In Scan files or folders, press Folder… and choose the folder of scans, or Browse… for single files. You can also type or paste paths; separate several with ;.
  3. Mizan checks the scans at once (Stop checking stops it), then says, for example, Checked 12 pages in 0.6 s: the card is made from them.
  4. Add your files, each with its Browse… button: Answer key file (or Key sheets), Roster file (CSV or Excel) and CLO mapping file (optional).
  1. Read What is graded on the right: each value, where it came from (for example 30 — key file) and the evidence under it. A scans folder named like CS213 Quiz 1 gives the course and the title.
  2. To change a value, type over it on the left: Exam title, Course code, Number of questions, Versions, Options per question.
  3. If a box at the top of What is graded asks a question, answer it with one of its buttons. With no answer key, for example, it offers Choose a key file…, Import from Remark…, Key sheets… and Grade with a provisional key (cannot be released).
  4. Press Grade exam. It is enabled only when nothing is left to answer; until then the text beside it says why. Mizan grades into a new folder inside your exams folder.

Advanced options

Open Advanced options for Sheet template or spec file, Output folder, Term, Student ID scheme, Cancel mode, Second review (No second review, Always or On high-stakes exams) and High-stakes exam.

Second review sets when a clearly filled double mark goes to a person. No second review, the default, scores it as wrong without review. Always sends every one to Review. On high-stakes exams sends them only when High-stakes exam is on. High-stakes exam, off by default, also uses stricter margins and sends erasures to Review: more review items, never fewer.

With the legacy answer sheet, Cancel mode is locked: the printed sheet decides how students change an answer.

When grading ends

The Scan screen follows the run. When it ends, a notice says how it went, with Review N items, Open results and Open exports folder; dismiss it with × or Esc. The exam is now listed on Exams, and its exports are already in its folder (Write exports after grading is on by default).

To stop or cancel

  • Cancel or Esc closes the card. One exam is graded at a time: a second card waits until the first run finishes.
  • While grading, Cancel grading… on Scan asks Cancel grading? Nothing is saved; your scan files are unchanged. A cancelled run cannot be resumed; Edit and grade again brings the card back as it was. Once the exam is being saved, it is too late to cancel.
05Chapter

The answer key

مفتاح الإجابة

Mizan needs the right answers for every version. Give them as a file, on answer sheets you fill in yourself, or from Remark's Excel export (Chapter 10). Until the real key arrives, you can grade with a provisional key that can never be released.

A key file

On the New exam card, fill Answer key file. The file is a CSV with one row per question and one column per version, for example question,A,B. Each entry is a letter (B), a choice of letters where either is accepted (A|C), a star to void the question (*), or empty while the answer is missing. A missing answer must be filled, or voided, before release. Keys that need several answers together, such as A+C, are refused. Chapter 13 shows the layouts and the points columns.

Key sheets: the key on an answer sheet

  1. Fill one answer sheet per version with the right answers. Bubble the student number as all zeros (or all nines) and bubble the version.
  2. Scan it with the students, anywhere in the stack, or give it in Key sheets on the New exam card.
  3. Nothing is scored yet. The key tag reads Key v1 · from key sheets · NOT CONFIRMED, and the notice offers Confirm the key in Setup.
  4. In Setup, the summary Key from answer sheets · Version A · … shows each question's bubble row as scanned, what it Reads, the Key entry and its Status.
  5. Decide every highlighted row (several marks, no mark, not read clearly): press the right letter, Accept A|C on a several-marks row, or Void.
  6. Press Confirm version A, or Confirm every version. These buttons stay disabled until every highlighted row is decided. The key is then in force and the exam is scored.
Check the question numbers

Each row shows the printed question number beside the bubbles. If it does not match the question, the sheet was read a row off. Do not confirm: rescan the key sheet flat and add it again.

  • A key sheet is never graded as a student, and its answers are never accepted on their own. The Scan screen lists key sheets apart from the students, as KEY A, KEY B.
  • A student who bubbles all zeros or all nines reads like a key sheet. Every sheet found for a version is named, so you can check it.
  • To read key sheets for an exam that already has a key: Setup › Read key from answer sheet… (Read key sheet… in a narrow window) › Key-sheet files › Read key sheets. Nothing changes until you confirm; Put aside drops them.
  • Undo never reverses a confirmation. To correct a confirmed key, change it: that makes a new key version.

No key yet: a provisional key

  1. On the card, choose Grade with a provisional key (cannot be released).
  2. Mizan infers each version's key from the students' most common confident answers. Every output is marked INFERRED, file names end in -INFERRED, and the results cannot be released.
  3. When the real key arrives: Setup › Replace key… › Key file › Replace and rescore. The notice after grading also offers Replace the key in Setup.

Correct one key entry

In Setup's Answer key and CLO mapping grid, type the letter in the question's cell. Every key change makes a new, numbered key version, rescores the exam and is recorded; the status bar reminds you that Key and mapping edits are recorded as audited events.

How the key stays out of sight

  • Review never shows the key. You decide what is marked from the paper.
  • The item analysis on Results hides the keyed option until you press Show key. A Remark import shows the key only as counts until Reveal key.
  • The exported item analysis and report.html leave the key out.
Note

The key is not hidden everywhere. Setup shows and edits the key letters, and the exam folder holds key.csv, the key in force (and, with key sheets, key_sheet_summary.html, the key as read). Keep the exam folder private.

06Chapter

Add scanned sheets

إضافة الأوراق الممسوحة ضوئيًا

Mizan reads scans straight from the scanner. Good scans mean fewer items to review. You can add more scans to a graded exam at any time, for another section or another day.

Scanning advice

  • Use a scanner with a document feeder. Choose 200–300 dpi in gray, or 600 dpi black and white.
  • Save as PDF or TIFF. JPEG and PNG also work. Turn off "compact PDF" compression.
  • Duplex is fine: blank backs are dropped, pages fed upside down are read upright, and a file added twice is ignored.
  • Rescan folded or torn sheets flat on the glass.
  • Do not use phone photos for students' sheets: every answer on a photo goes to review. A key sheet may be photographed: the whole sheet, from straight above, evenly lit.
  • A single file over 2 GB is refused. Split very large scans.
  • Mizan does not watch the scanner's folder. Grade the folder when scanning ends.
  • Keep scans on your institution's device, never in a cloud or network folder.

What the Scan screen shows

Across the top, the tiles THROUGHPUT, PAGES, AUTO-ACCEPTED, FIRST RESULT and REMAINING. Below them, the Pipeline, and Sheets with counts of Auto, Review and Rejected: arrows move between thumbnails and Enter opens a sheet's review item. On the right, Exceptions by code (Enter opens the review queue filtered to that code), Batch reconciliation and Activity. Open review · N (Ctrl+4) takes you to Review.

Add a later batch

  1. Open the exam, go to Scan and press Add scans….
  2. In Scan files or folders to add, use Browse… or Folder…, or type the paths.
  3. Press Add and regrade (Enter).
  4. Every page is graded again, with the new ones as the next batch. Your review decisions carry over, and a re-read that disagrees with a decision is flagged.

While a batch is graded, the exam is busy: Review says the exam is being graded and the Exams row reads Scanning. If the exam was released, release it again afterwards.

Add a roster after grading

Setup › Add roster… › Roster file › Add roster and match students. Every sheet is matched again and your decisions carry over. A roster cannot be removed once added.

07Chapter

Review

المراجعة

Mizan never guesses. Every mark, student number or page it is not sure about waits in Review until a person decides. Each decision is recorded, and the results update as you go.

The four lanes

Review items sit in four lanes, shown as chips with counts at the top of the screen. Marks: answer marks, such as a low-confidence mark or multiple marks. Identity: who a sheet belongs to. Capture: page problems, such as unreadable files or poor scans; help (F1) gives the fix. Scoring: a version not identified, or a probable mis-key, where the strongest students contradict the key. A mis-key holds release until you change the key, accept a second answer, void the question, or keep the key with a reason.

Decide a mark

  1. Pick an item in the Exception queue. Items are grouped by code, with a count.
  2. Look at the scan. The chips above it switch Registered or Original (F2), Overlay (Space), All bubbles and Zoom (+ and −). Below it, Fill by bubble and Student's other answers help you judge.
  3. On the right are the suggestion and WHAT IS MARKED?, with the options, Blank (Backspace), Multi (Ctrl+M) and Unreadable (Ctrl+U).
  4. Press Enter, or Accept suggestion, to accept. Or press the letter or number of another answer.
  5. Apply to group · N (Shift+Enter) applies the same decision to the rest of the group, when the group allows it.
  6. Other actions: Defer (Ctrl+D) moves the item to the end of the queue; Escalate to instructor (Ctrl+E); Add to rescan list (Ctrl+R). The note field takes a note in Arabic or English; notes are personal data.

Unreadable, Escalate to instructor and Add to rescan list move an item aside but do not close it. It stays in the queue, still counts as open and still holds release until someone decides it. Unreadable also records the answer as unreadable, never as blank. No screen shows yet which items are escalated or on the rescan list; their state is kept in review_queue.json.

Override the suggestion

  1. Choose an answer that differs from the suggestion. WHY OVERRIDE THE SUGGESTION? appears, with reasons such as Ambiguous mark, Erasure residue, Stray mark, Other and more.
  2. The main button reads Choose a reason until you pick one.
  3. Other needs a note: the button reads Write why in the note until there is one.
  4. Press Enter to record the decision with its reason.

Decide who a sheet belongs to

  1. In the Identity lane the scan shows the student-number grid, and What the channels read gives the number read.
  2. WHO IS THIS? lists up to three roster candidates. Press 1–3 to choose one, or N for Not on roster.
  3. Or type the number under NOT LISTED? TYPE THE STUDENT NUMBER and press Use number, or search with Roster search (/).
  4. Press Enter to accept. Duplicate (D) is shown but not recorded yet: choose a student or N instead.

Undo and help. Ctrl+Z, or the undo button in the top bar, undoes the last decision. The record is never rewritten: the undo is recorded too. F1 explains the current item's code and what to do.

Keyboard

Review keys work while the review area has focus. With an Arabic keyboard, keys work by position: under the Arabic (101) layout the A key still picks A, and Arabic option letters (أ ب ج د هـ) and Arabic-Indic digits work too. Settings › Review keymap lists every key. If single-letter keys get in your way, turn off Single-key shortcuts in Settings (Chapter 12).

08Chapter

Results and item analysis

النتائج وتحليل الفقرات

Results shows how the class did, how each question worked, and whether the exam can be released. It updates as you decide review items.

  1. Press Results (Ctrl+5), or Open results on the notice or in the exam's drawer.
  2. Read the tiles: STUDENTS, MEAN, PASS RATE, CRONBACH α, SEM and OPEN EXCEPTIONS.
  3. Grade distribution counts students per letter grade on the Saudi grade scale, with the pass mark. Switch between Chart and Table.
  4. Score distribution shows percentages in 10 % bins, with the pass mark and the mean.
  5. Item analysis lists, per question, p, r ir, 95 % CI, Discrimination, the Options chosen, Stability and a Flag. Flagged questions come first. The keyed option stays hidden until Show key.
  6. Release readiness lists what still blocks release (Chapter 9).

Reading the item analysis

ColumnWhat it tells you
pThe share of students who answered correctly: 0.85 means 85 %. Below 0.30 is hard; above 0.90 is easy.
r ir and 95 % CIDo strong students get this question right more often than weak ones? 0.30 or more is good, 0.20–0.29 acceptable, 0.10–0.19 marginal, below 0.10 needs a look, below 0 suggests a flawed question or a wrong key. The interval shows how sure the figure is.
OptionsHow often each option was chosen.
StabilityFor a class of fewer than 1,000 students, how often a flag fires again when Mizan re-draws the class 1,000 times. Mizan also checks the flag at both ends of its 95 % interval; for 1,000 students or more, that check alone decides. A flag that does not hold up is marked "proposed" and never blocks release.
Cronbach αHow consistently the whole test measures. 0.80 or more suits an end-of-course exam; 0.90 or more a high-stakes one.
SEMStandard error of measurement: how far, in points, a score may sit from the student's true score. Smaller is better.

With fewer than 10 students, Mizan shows only counts, p and option shares. With 10 to 29 students, r ir and alpha are marked as low confidence.

The grade scale

Percent95+90858075706560< 60
LetterA+AB+BC+CD+DF
Arabicأ+أب+بج+جد+دهـ

Each band runs from its percent up to the next one; 60 % passes. The results file also gives each student's GPA out of 5 and out of 4.

Two empty states: Results wait for the key, with Confirm the key in Setup, while a key from key sheets is not yet confirmed; and No results yet before the first grading run.

09Chapter

Release and export

اعتماد النتائج وتصديرها

Results go nowhere until you release them. Release is a deliberate act, and Mizan refuses it while anything is still open.

What blocks release

Release readiness on Results is a checklist. Each open line has a chip: Open takes you to the right Review lane, Setup to Setup. Release is blocked by:

  • open review items of ERROR or BLOCKER level (the serious ones; smaller warnings never hold release), including probable mis-keys;
  • a key read from key sheets that is not confirmed yet;
  • a provisional key inferred from the sheets;
  • the mis-key check, while it is still computing;
  • no key, or a key with empty entries (fill them, or void them with *).

The checklist also counts provisional totals, pages not attributed to a student, versions inferred and responses pending review.

Release the results

  1. On Results, press Release results…. It is enabled only when nothing blocks release; otherwise the reason shows beside it in red.
  2. A bar asks Release the results? with Release and Cancel. The keyboard starts on Cancel, so Enter never releases by accident.
  3. Read the note under it: release freezes the score run and the key version in the audit log, and writes the exports with the Blackboard upload.
  4. Press Release. A message confirms the key version and score run, and where the exports went. Without a roster there is no Blackboard upload.
After release

Any later change, such as a review decision, a key change or added scans, cancels the release. The upload file is removed at the next export until you release again.

Export

With Settings › Write exports after grading on (the default), the exports are written into the exam's folder each time a run ends. To write them again by hand:

  1. On Results, press Export….
  2. Press Write all exports. Or, after release, fill Blackboard column ID (optional) and press Write Blackboard CSV.
  3. Press Open exports folder to see the files, then Close (or Esc).

After a later decision, Mizan reminds you that these exports were written before your latest changes: Write all exports in Results updates them. Write Blackboard CSV stays disabled, with the reason, while the key is inferred or the exam has no roster.

The files in the exam folder

FileWhat it holds
results.xlsx, results.csvOne row per student: number, name, section, version, status, raw score, maximum, percent, letter grade (English and Arabic), GPA out of 5 and out of 4, and each answer. Roster students without a sheet are listed as absent.
item_analysis.xlsxwith item_analysis.csv, test_stats.csvHow each question worked, flags such as a probable mis-key, and a test summary with alpha and SEM. Written without the key.

Every export is classified Restricted (مقيد): the Excel and HTML files show the label, and manifest.json records it for the CSV and JSON files. With a provisional key, file names end in -INFERRED and carry a warning.

The Blackboard upload

The file holds the username and score only: no names, no sections. A student whose result is not final is left out, so Blackboard keeps their old value. Mizan assumes each Blackboard username is the student number in your roster; check this before your first upload. To fill an existing grade column, give its column ID: the number after | in the column header of a Grade Center download. You upload the file yourself; Mizan does not connect to Blackboard.

10Chapter

Import from Remark and compare

الاستيراد والمقارنة

Mizan can take the key, points and learning objectives from Remark Office OMR's Excel exports, and check a Mizan run against Remark's results for the same sheets.

Mizan reads only Remark's documented, graded Excel exports: the Advanced Grade reports saved as .xlsx (the Student Response Report with the answer key, the Student Statistics Report and the Test Statistics Report). It never opens Remark's own .rmx or .aky files.

Import on a new exam

  1. On the New exam card, or on the empty Exams screen, press Import from Remark export….
  2. In Remark workbooks, choose the exports (separate several with ;). Points file (optional) is for points Remark's totals cannot settle: a CSV such as question,points_A,points_B, one row per question, empty cells worked out by Mizan. Press Read export.
  3. Nothing changes yet. Check the import: per version, the points and the key as counts, with the letters hidden until Reveal key; the learning objectives, each marked "imported, needs review"; and any key sheets Remark graded as students, which are left out.
  4. Press Use this import, or Put the import aside, or Back to the form.
  5. The card now takes the key, versions and question count from the import; Clear the Remark import undoes it.

Import into a graded exam

Setup › Import from Remark… (Remark… in a narrow window), then Apply key and points. The imported key comes into force as a new key version and the exam is rescored. A graded exam's points cannot change: an export whose points differ is shown as not applicable, with what to do (create the exam from the import instead). The learning objectives are only listed here; a graded exam's CLOs change only with Setup › CLO file › Replace CLOs. CLO rows imported from Remark stay a draft until you approve them with Setup › Approve imported mappings; until then the outcome tables are marked as a draft.

When an import is refused, Mizan says Refused: nothing was imported or changed and then what to do; it may offer Use the suggested points. Export student numbers from Remark as text: a number Excel already shows as 2.2E+09 cannot be recovered.

Compare a run with Remark

  1. On Results, press Compare with Remark… (Remark… in a narrow window, as in Figure 8.1).
  2. In Remark workbooks to compare, give Remark's exports of the same sheets; press Compare.

10Side-by-side test guide

Run a side-by-side test with Remark

التجربة بالتوازي مع Remark

For instructors who grade with Remark: grade one exam in both programs, check each difference against the paper and send back counts and notes. Only Remark's grades count, as the manual advises against grading real exams with a Windows test build: do not release Mizan's results, give them to students or upload them to Blackboard.

Before you start

  • An exam on the legacy answer sheet, graded in Remark as usual, with its scans saved as PDF or TIFF files.
  • The Advanced options of the New exam card at their defaults, No second review and High-stakes exam off, so that results compare. A clearly filled double mark is then scored as wrong without review; an unsure one still goes to Review.
  • Your institution's computer, used by you alone, with an encrypted disk, and folders outside OneDrive, other synced folders and network drives. On Windows, Mizan does not yet refuse OneDrive or limit its folders to your account (Chapter 14).

Steps

  1. Download the latest Windows file from the project's Releases page, check it against SHA256SUMS with your IT team, unzip it and run omr-desktop.exe (Chapter 2).
  2. Scan the sheets to PDF or TIFF at 200 to 300 dpi in gray, or 600 dpi black and white, with "compact PDF" compression off (Chapter 6). Grade the exam in Remark as usual, from the same files if you can.
  3. In Remark, export the graded results to Excel: the Advanced Grade reports as .xlsx, including the Student Response Report with the answer key, and the student numbers as text.
  4. In Mizan, press New exam and choose the scan files. Press Import from Remark export…, give it the workbook (several, separated by ;), then press Read export and Use this import, so that Mizan grades with Remark's key and points. Answer any question the card asks and press Grade exam. When the run ends, write down the Scan screen's figures (Table 10.2).
  5. Open Review (Chapter 7) and, before you decide anything, write down the count on the Marks lane chip. Then decide the items. For a sheet held for its version, in the Scoring lane, press the right version letter (with a reason if it is not the suggestion), then Enter, or Enter alone to accept the suggestion. An item you defer or escalate stays open.
  6. On Results, press Compare with Remark…, give the same workbook and press Compare. Check each row of Differences to adjudicate against the paper (Table 10.1). Write down your counts before any Queue for review, which adds each difference on an answer Mizan accepted on its own to Review.

13Chapter

Files and formats

الملفات وصيغها

Mizan reads two kinds of answer sheet and a few simple files you can make in Excel. Save files as CSV with commas, semicolons or tabs, as Excel saves them. Arabic text works in UTF-8, UTF-16 or Windows-1256.

Answer sheets

  • The legacy answer sheet, already in use: landscape A4, up to 100 questions with options A–E, a 10-digit student number and a version bubble (A–D). It also carries a section, a date, gender and the exam type (Quiz 1, Quiz 2, Quiz 3, Midterm, Final). You tell Mizan how many questions your exam uses. Students change an answer by erasing it.
  • Your own printed form. Mizan prints A4 sheets made for one exam: 1 to 1,000 questions, 2 to 10 options, up to 26 versions, and a student-number grid of the length you choose. Options can be printed as A–J, as Arabic letters (أ ب ج د هـ and on; rows then run right to left) or as numbers. Instructions are printed in English and Arabic. Each sheet carries a code that ties it to this exam: a sheet from another exam, or a forged one, is held for a person to check. IT staff make these forms with the command line (Appendix A).

The form's PDF is set to print without scaling: do not let the printer shrink it to fit. Its secret code stays in your private folder, never beside the PDF, so the PDF can go to the print shop.

Where your data lives and how it is protected

أين تُحفظ بياناتك وكيف تُحمى

Mizan runs on your computer and keeps its files there, in two folders. It makes no network calls of its own.

Your exams folder

OMR Exams in your home folder, unless you chose another. Each exam gets its own folder:

OMR Exams/
  cs-213-quiz-1/              one exam
    project.omrproj/          the exam's record: never edit or move anything inside
      project.db              every decision, in order
      objects/                a copy of every scanned page
    results.xlsx              the exports (Chapter 9)
    item_analysis.xlsx
    report.html
    key.csv
    manifest.json
    …

Back up the whole exam folder. It holds a copy of every scan: treat it like the paper scripts.

Your private folder

  • Windows: %APPDATA%\omr
  • Linux: ~/.local/share/omr
  • Either: the folder named by OMR_KEY_DIR, if your IT team set one

It holds this computer's signing key, a signed checkpoint of each exam's record (a fingerprint of its latest state, not a backup), the secret codes of your own printed forms, and the desktop app's settings. Back it up separately and keep it private. If it is lost, Mizan can no longer tell when an older copy of an exam was put back.

The safeguards

  1. Marks are read without the key. The part of Mizan that reads the bubbles never sees the key, so a doubtful mark cannot be nudged towards the right answer, or away from it. Reviewers work without the key too.
  2. When Mizan is not sure, a person decides. An answer it cannot read is never counted as blank. Choosing something other than its suggestion needs a reason.
  3. Every decision is recorded, and the record cannot be quietly changed. Each decision, key change and release is written in order, each entry sealed to the one before; the chain is signed with this computer's key, and a signed checkpoint is kept in your private folder. If anyone edits, cuts or swaps the record, Mizan refuses to open the exam and says why.
  4. Release is your decision. Results go nowhere until you release them, and any later change cancels the release.
  5. Mizan makes no network calls of its own. Apart from the system's own file pickers, the only program the desktop app starts is your file manager, to show a folder. The Blackboard file is a file you upload yourself. Keep both folders out of cloud and network folders: on Windows, Mizan does not yet refuse OneDrive.
  6. The same scans give the same decisions, on one processor core or many, in any page order. This was tested on Linux; identical decisions on Windows are not proven yet.
  7. Student numbers are masked on the command line to their last three digits. Showing a full number is recorded, and so is every exported picture of an answer.
  8. Exports are classified Restricted. Text cells in CSV files that start with =, +, - or @ get a leading ', so a spreadsheet does not run them as formulas.

"No network calls of its own" comes from a review of Mizan's code and of the libraries it uses: none of them opens a network connection. It was not confirmed by watching network traffic.

Keep exam data safe
  • Use a device with an encrypted disk. Mizan does not encrypt the exam folder itself.
  • Never use OneDrive, Dropbox, iCloud, Nextcloud or a network drive. On Linux, Mizan refuses them all. On Windows, it so far refuses only network paths and Dropbox-style folders.
  • On Linux, exam folders are readable by you only. On Windows this protection is not built yet, and the signing key is not yet held in Windows' own key store.
  • Do not open, edit or copy files inside project.omrproj. If anything inside changes, Mizan refuses to open the exam.

Not covered yet: looking at students in the desktop app is not recorded, and the seal trusts this computer. On another computer, Mizan checks only that the record is consistent with itself.

16Chapter

Known limits

القيود المعروفة

Mizan 0.1.0 is a first version. These limits apply today.

Computers

  • No version for Mac.
  • Windows: unsigned test builds only, no installer, and some file protections missing (Chapter 14).
  • The desktop app has not yet been used in a real window.

Scanning

  • Mizan does not watch the scanner's folder. Grade the folder when scanning ends.
  • Phone photos of students' sheets: every answer goes to review.
  • A sticker or white-out over one empty bubble on the legacy sheet reads as blank.
  • A very light second mark can look like an erased one.
  • The legacy sheet supports only "erase to change"; a mirrored scan is held.
  • Own forms print as PDF only.

Grading and review

  • Keys that need several answers together (A+C) are not supported. Use A|C, or void the question.
  • Small warnings are counted, not queued for review.
  • Each decision in Review is made by one reviewer; no second person checks it yet. (Second review in Advanced options is about double marks, not a second reviewer.)
  • Two sheets with one student number and different answers cannot be marked as duplicates.
  • If nobody chose the keyed answer, Mizan flags the question but does not block release. Check such questions yourself.
  • Stopping a grading run keeps nothing; grade the scans again.
  • The default student-number scheme accepts intake years up to 2030.

Rosters

  • Matching against a real class roster has not been proven yet. Check identity items with care.
  • A roster cannot be removed once added.

Security

  • The exam folder is not encrypted. Use an encrypted device.
  • Looking at students in the desktop app is not recorded.

Moving from Remark

  • Only Remark's graded Excel export is read; not its CSV or SPSS exports.
  • Remark's results cannot become an exam in Mizan without the scans: scan the sheets and grade them.
  • Imported learning objectives all start in the K domain. Correct clo.csv, then replace and approve it.
  • A graded exam's points cannot change. Create the exam from the Remark import instead.
  • A comparison holds release only if you queue its differences for review.

Accreditation

  • NCAAA tables come as Excel and CSV, not as the official Word forms.
  • ABET summaries are not available.

The desktop app

  • No keymap editor, no dragging files onto the window, no menu of recent exams folders.
  • An added batch or a roster run can be cancelled only by closing the window.

omr sheet render --spec spec.json --out sheets.pdf --copies 120

--project takes the exam folder or its project.omrproj. --copies is the number of sheets per version.

Review decisions (--decision): ack accepts the suggestion; otherwise a letter, blank, multi:A+C, unreadable, student:<number>, not-on-roster or form:B. A decision other than the suggestion needs --reason, for example AMBIGUOUS_MARK, ERASURE_RESIDUE, ID_CORRECTION, or OTHER with --note. A probable mis-key (SCO-001) takes other decisions: a letter changes the key to that answer, multi accepts the key or the flagged answer, void voids the question, and ack keeps the key and needs --reason and --note. --defer, --escalate, --rescan and --undo take no decision; --group applies one to the item's whole group.

Measure speed

omr bench <scans folder or files>... --template <legacy> --questions <N>
          [--forms A,B,C,D] [--threads 1,2,4] [--repeat N] [--first 30]
          [--scratch <folder>] [--out bench.json]

For each thread count in --threads (1, 2 and 4 by default), omr bench prints two speeds in pages a second: recognition, reading the pages, and full pipeline (no store), which adds identity, versions, scoring and the review queue. --repeat runs each count several times and keeps the best. It then grades the first sheets (--first, 30 by default) end to end, with the store and every export, and prints the time to first result. It always grades with a key it works out from the sheets, so it needs no key file and measures speed only, never accuracy. --template (or --spec for your own form) and --questions are required; without --forms, the legacy sheet is taken to have versions A and B. --out writes the figures as JSON.

omr grade prints two summary lines: the answers accepted on their own, with AR, and the times. There, pages/s is the same measure as THROUGHPUT on the Scan screen, and wall is the whole command, exports included. The desktop app always grades on every core; on the command line, --threads N sets the count.
